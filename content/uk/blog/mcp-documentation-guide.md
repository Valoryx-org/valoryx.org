Model Context Protocol (MCP) — це відкритий стандарт, що дозволяє ШІ-помічникам взаємодіяти із зовнішніми інструментами та джерелами даних через структурований інтерфейс. Замість копіювання тексту у вікно чату з надією, що модель зрозуміє контекст, MCP дає помічнику прямий, типізований доступ до ваших систем — читання файлів, виконання пошуку, створення контенту — все через чітко визначені виклики інструментів.

Для команд документації це кардинально змінює процес роботи. Ваш ШІ-помічник перестає бути генератором тексту, що працює з застарілим контекстом, і стає учасником, який читає вашу фактичну документацію, шукає по базі знань і вносить зміни, які ви можете переглянути перед публікацією.

Valoryx поставляється з вбудованим MCP-сервером із 26 інструментами. Жодних плагінів для встановлення, жодних API-ключів для налаштування. Якщо у вас є працюючий екземпляр, MCP-сервер вже там.

## Що насправді робить MCP

MCP визначає протокол для виявлення та виклику інструментів. ШІ-клієнт (наприклад, Claude Desktop) підключається до MCP-сервера, запитує, які інструменти доступні, та викликає їх зі структурованими параметрами. Сервер виконує операцію та повертає структуровані результати.

Це відрізняється від «ШІ-функцій», прикрученених до продукту. Тут немає пропрієтарної інтеграції. Будь-який MCP-сумісний клієнт працює. [Специфікація MCP](https://modelcontextprotocol.io) відкрита, і кілька ШІ-помічників вже підтримують її.

Практичний результат: ви можете попросити Claude «знайти всі сторінки, що згадують автентифікацію», і він дійсно шукатиме у вашому екземплярі документації, а не галюцинуватиме назви сторінок із навчальних даних.

## 13 вбудованих інструментів

MCP-інструменти Valoryx поділяються на чотири категорії:

### Інструменти читання
Вони отримують контент без модифікації.

- **get_page** — Отримати одну сторінку за ID або шляхом. Повертає заголовок, markdown-контент, метадані та позначку часу останньої зміни.
- **get_workspace** — Перелічити всі workspace з кількістю сторінок та налаштуваннями.
- **get_page_tree** — Повернути повне навігаційне дерево для workspace. Корисно для розуміння структури документації перед внесенням змін.

### Інструменти пошуку
Повнотекстовий пошук на базі того ж рушія Bleve, що керує веб-інтерфейсом.

- **search_pages** — Пошук по всіх сторінках у workspace. Підтримує фразові запити, пошук за конкретними полями та булеві оператори.
- **search_by_tag** — Знайти сторінки з певними тегами. Корисно для аудиту: «покажи все з тегом `deprecated`».
- **search_recent** — Знайти сторінки, змінені за останні N днів. Зручно для перегляду нещодавніх змін.

### Інструменти запису
Створюють або модифікують контент. Кожна операція запису створює запис у леджері, тому зміни відстежуються і безпечні для синхронізації.

- **create_page** — Створити нову сторінку із заголовком, контентом, батьківським шляхом і тегами.
- **update_page** — Замінити контент існуючої сторінки. Попередня версія зберігається в історії.
- **move_page** — Змінити позицію сторінки в навігаційному дереві.
- **delete_page** — М'яке видалення сторінки (відновлюється з панелі адміністратора).

### Адміністративні інструменти
Операції управління workspace та користувачами.

- **list_users** — Отримати всіх користувачів з їхніми ролями. Корисно для аудиту доступу.
- **get_activity_log** — Отримати нещодавню активність (редагування, входи, зміни дозволів).
- **get_sync_status** — Перевірити стан git sync для workspace — час останньої синхронізації, очікувані зміни, конфлікти.

## Налаштування Claude Desktop

Щоб підключити Claude Desktop до вашого екземпляру Valoryx, додайте запис MCP-сервера у файл конфігурації. На macOS він знаходиться за адресою `~/Library/Application Support/Claude/claude_desktop_config.json`. На Windows — `%APPDATA%\Claude\claude_desktop_config.json`.

```json
{
  "mcpServers": {
    "valoryx-docs": {
      "command": "npx",
      "args": [
        "-y",
        "@anthropic-ai/mcp-client",
        "--server-url",
        "https://docs.yourcompany.com/api/mcp"
      ],
      "env": {
        "MCP_API_KEY": "your-api-key-here"
      }
    }
  }
}
```

Згенеруйте API-ключ у панелі адміністратора Valoryx у розділі **Settings > API Keys**. Ключ успадковує дозволи користувача, який його створив, тому використовуйте окремий сервісний обліковий запис із відповідною RBAC-роллю, якщо хочете обмежити можливості ШІ.

Для Community Edition, що працює локально, URL зазвичай `http://localhost:3000/api/mcp`.

## Практичні приклади

Після підключення ось конкретні речі, які ви можете робити:

### Пошук застарілого контенту

```
"Знайди всі сторінки в workspace Engineering, які не оновлювалися 
протягом останніх 90 днів"
```

Помічник викликає `search_recent` із вікном у 90 днів, інвертує результат відносно `get_page_tree` і повертає список потенційно застарілих сторінок. Ви отримуєте шляхи сторінок, дати останньої зміни та останніх редакторів — достатньо для призначення завдань на перегляд.

### Аудит узгодженості

```
"Знайди всі сторінки, що посилаються на наш старий API endpoint 
api.example.com/v1, та перелічи їх"
```

Це викликає `search_pages` з рядком старого endpoint. Ви отримуєте список кожної сторінки, що все ще посилається на застарілий URL, з оточуючим контекстом. Жодного ручного grep по репозиторію документації.

### Створення та оновлення контенту

```
"Прочитай поточний посібник з автентифікації, потім онови його, щоб 
включити новий процес входу через passkey. Збережи існуючу структуру."
```

Помічник викликає `get_page` для читання поточного контенту, створює чернетку оновлення та викликає `update_page` для його застосування. Попередня версія залишається в історії. Якщо налаштовано [git sync](/docs/guides/git-integration/), редагування з'являється як коміт у вашому репозиторії.

### Перегляд нещодавніх змін

```
"Покажи мені все, що змінилося за останній тиждень у всіх 
workspace"
```

Викликає `search_recent` із вікном у 7 днів. Повертає зведення того, що змінилося, хто змінив і коли. Корисно для щотижневих переглядів документації без входу у веб-інтерфейс.

## Що це означає для обслуговування документації

Традиційний процес обслуговування документації: хтось помічає, що документація неправильна, створює тікет, хтось інший врешті оновлює сторінку. Проміжок між «помітив» і «виправив» зазвичай тижні.

З MCP процес стає таким: попросити ШІ провести аудит розділу, переглянути знахідки, схвалити зміни. Проміжок скорочується до хвилин. Не тому, що ШІ пише кращу документацію — ні, не надійно — а тому, що вузьким місцем завжди було знайти, що не так, і внести зміну, а не скласти текст.

Це особливо добре працює для механічних оновлень: зміни URL, перейменування термінів, оновлення номерів версій, повідомлення про застарілість. Той тип змін, що виснажливий для людей і зрозумілий для ШІ зі структурованим доступом до контенту.

Більше про використання MCP для підтримки актуальності документації читайте у статті [Як підтримувати документацію актуальною](/blog/keep-docs-up-to-date/).

## Обмеження, які варто знати

MCP-інструменти оперують окремими сторінками. Інструменту «переписати весь сайт документації» немає — навмисно. Масштабна реструктуризація все ще потребує людського судження щодо інформаційної архітектури.

Інструменти запису створюють реальні зміни. Якщо ви налаштуєте Claude Desktop з API-ключем рівня адміністратора, ШІ зможе видаляти сторінки. Використовуйте RBAC для відповідного обмеження дозволів API-ключа. Роль «Editor» може читати та писати контент, але не може видаляти workspace або керувати користувачами.

Якість пошуку залежить від вашого контенту. Якщо ваша документація використовує непослідовну термінологію, ШІ знайде непослідовні результати. MCP робить пошук швидким, але не виправляє основні проблеми контенту.

## Початок роботи

1. [Встановіть Valoryx](/install/) — один бінарний файл, без залежностей, працює менш ніж за 2 хвилини
2. Згенеруйте API-ключ у панелі адміністратора
3. Додайте конфігурацію MCP-сервера в Claude Desktop
4. Почніть із процесу тільки для читання: пошук і аудит, перш ніж увімкнути запис

[Документація MCP](/mcp/) містить повну довідку API для всіх 26 інструментів, включаючи типи параметрів і схеми відповідей.

Обслуговування документації не повинно бути ручним процесом. Зі структурованим протоколом між вашим ШІ-помічником і платформою документації рутинні частини — пошук застарілого контенту, перевірка узгодженості, внесення механічних оновлень — стають тим, що можна делегувати з упевненістю.
