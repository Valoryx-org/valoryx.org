Model Context Protocol (MCP) — это открытый стандарт, позволяющий ИИ-ассистентам взаимодействовать с внешними инструментами и источниками данных через структурированный интерфейс. Вместо копирования текста в окно чата в надежде, что модель поймёт контекст, MCP даёт ассистенту прямой типизированный доступ к вашим системам — чтение файлов, выполнение поиска, создание контента — всё через чётко определённые вызовы инструментов.

Для команд, работающих с документацией, это фундаментально меняет рабочий процесс. Ваш ИИ-ассистент перестаёт быть генератором текста, работающим из устаревшего контекста, и становится участником, который читает реальную документацию, ищет по всей базе знаний и вносит правки, которые вы можете проверить перед публикацией.

Valoryx поставляется со встроенным MCP-сервером с 13 инструментами. Никаких плагинов для установки, никаких API-ключей для настройки. Если у вас запущен экземпляр, MCP-сервер уже работает.

## Что на самом деле делает MCP

MCP определяет протокол для обнаружения и вызова инструментов. ИИ-клиент (например, Claude Desktop) подключается к MCP-серверу, запрашивает доступные инструменты и вызывает их со структурированными параметрами. Сервер выполняет операцию и возвращает структурированные результаты.

Это отличается от «ИИ-функций», прикрученных к продукту. Здесь нет проприетарной интеграции. Любой MCP-совместимый клиент работает. [Спецификация MCP](https://modelcontextprotocol.io) открыта, и несколько ИИ-ассистентов уже поддерживают её.

Практический результат: вы можете попросить Claude «найти все страницы, упоминающие аутентификацию», и он действительно будет искать по вашему экземпляру документации, а не генерировать названия страниц из обучающих данных.

## 13 встроенных инструментов

MCP-инструменты Valoryx делятся на четыре категории:

### Инструменты чтения
Они извлекают контент без модификации.

- **get_page** — Получить одну страницу по ID или пути. Возвращает заголовок, markdown-контент, метаданные и временную метку последнего изменения.
- **get_workspace** — Список всех workspace с количеством страниц и настройками.
- **get_page_tree** — Получить полное навигационное дерево для workspace. Полезно для понимания структуры документации перед внесением изменений.

### Инструменты поиска
Полнотекстовый поиск на базе того же движка Bleve, что используется в веб-интерфейсе.

- **search_pages** — Поиск по всем страницам в workspace. Поддерживает фразовые запросы, поиск по полям и булевы операторы.
- **search_by_tag** — Найти страницы с определёнными тегами. Полезно для аудита: «покажи всё с тегом `deprecated`».
- **search_recent** — Найти страницы, изменённые за последние N дней. Удобно для обзора недавних изменений.

### Инструменты записи
Они создают или изменяют контент. Каждая операция записи создаёт запись в реестре, поэтому изменения отслеживаются и безопасны для синхронизации.

- **create_page** — Создать новую страницу с заголовком, контентом, родительским путём и тегами.
- **update_page** — Заменить контент существующей страницы. Предыдущая версия сохраняется в истории.
- **move_page** — Изменить позицию страницы в навигационном дереве.
- **delete_page** — Мягкое удаление страницы (восстановимо через панель администрирования).

### Инструменты администрирования
Операции управления workspace и пользователями.

- **list_users** — Получить всех пользователей с их ролями. Полезно для аудита доступа.
- **get_activity_log** — Получить недавнюю активность (правки, входы, изменения разрешений).
- **get_sync_status** — Проверить состояние git-синхронизации для workspace — время последней синхронизации, ожидающие изменения, конфликты.

## Настройка Claude Desktop

Чтобы подключить Claude Desktop к вашему экземпляру Valoryx, добавьте запись MCP-сервера в файл конфигурации. На macOS он находится в `~/Library/Application Support/Claude/claude_desktop_config.json`. На Windows — `%APPDATA%\Claude\claude_desktop_config.json`.

```json
{
  "mcpServers": {
    "valoryx-docs": {
      "command": "npx",
      "args": [
        "-y",
        "@anthropic-ai/mcp-client",
        "--server-url",
        "https://docs.yourcompany.com/api/mcp"
      ],
      "env": {
        "MCP_API_KEY": "your-api-key-here"
      }
    }
  }
}
```

Сгенерируйте API-ключ в панели администрирования Valoryx в разделе **Settings > API Keys**. Ключ наследует права пользователя, который его создал, поэтому используйте выделенную сервисную учётную запись с соответствующей RBAC-ролью, если хотите ограничить возможности ИИ.

Для Community Edition, работающего локально, URL обычно `http://localhost:3000/api/mcp`.

## Практические примеры

После подключения вот конкретные вещи, которые можно делать:

### Поиск устаревшего контента

```
"Найди все страницы в workspace Engineering, которые не обновлялись 
за последние 90 дней"
```

Ассистент вызывает `search_recent` с 90-дневным окном, инвертирует результат относительно `get_page_tree` и возвращает список потенциально устаревших страниц. Вы получаете пути к страницам, даты последнего изменения и имена последних редакторов — достаточно для назначения задач на проверку.

### Аудит согласованности

```
"Найди все страницы, ссылающиеся на наш старый API-эндпоинт 
api.example.com/v1, и перечисли их"
```

Это вызывает `search_pages` со строкой старого эндпоинта. Вы получаете список каждой страницы, всё ещё ссылающейся на устаревший URL, с окружающим контекстом. Никакого ручного grep по репозиторию документации.

### Написание и обновление контента

```
"Прочитай текущее руководство по аутентификации, затем обнови его, 
чтобы включить новый процесс входа через passkey. Сохрани существующую структуру."
```

Ассистент вызывает `get_page` для чтения текущего контента, готовит обновление и вызывает `update_page` для его применения. Предыдущая версия остаётся в истории. Если настроена [git-синхронизация](/docs/guides/git-integration/), правка появляется как коммит в вашем репозитории.

### Обзор недавних изменений

```
"Покажи всё, что изменилось за последнюю неделю во всех workspace"
```

Вызывает `search_recent` с 7-дневным окном. Возвращает сводку того, что изменилось, кто изменил и когда. Полезно для еженедельных обзоров документации без входа в веб-интерфейс.

## Что это значит для обслуживания документации

Традиционный рабочий процесс обслуживания документации: кто-то замечает, что документация неверна, создаёт тикет, кто-то другой в конце концов обновляет страницу. Разрыв между «заметил» и «исправил» обычно составляет недели.

С MCP рабочий процесс становится: попросить ИИ провести аудит раздела, проверить результаты, одобрить изменения. Разрыв сокращается до минут. Не потому что ИИ пишет лучшую документацию — он не пишет, по крайней мере не надёжно — а потому что узким местом всегда было найти, что неправильно, и внести правку, а не сочинить текст.

Это особенно хорошо работает для механических обновлений: изменения URL, переименование терминологии, обновление номеров версий, уведомления об устаревании. Тот тип изменений, который утомителен для людей и прост для ИИ со структурированным доступом к контенту.

Подробнее об использовании MCP для поддержания документации в актуальном состоянии — в статье [Как поддерживать документацию в актуальном состоянии](/blog/keep-docs-up-to-date/).

## Ограничения, о которых стоит знать

MCP-инструменты оперируют отдельными страницами. Нет инструмента «перепиши весь сайт документации» — по замыслу. Масштабная реструктуризация всё ещё требует человеческого суждения об информационной архитектуре.

Инструменты записи вносят реальные изменения. Если вы настроите Claude Desktop с API-ключом уровня администратора, ИИ сможет удалять страницы. Используйте RBAC для ограничения разрешений API-ключа. Роль «Editor» позволяет читать и писать контент, но не удалять workspace или управлять пользователями.

Качество поиска зависит от вашего контента. Если ваша документация использует непоследовательную терминологию, ИИ найдёт непоследовательные результаты. MCP делает поиск быстрым, но не исправляет проблемы с качеством контента.

## Начало работы

1. [Установите Valoryx](/install/) — один бинарный файл, без зависимостей, запуск менее чем за 2 минуты
2. Сгенерируйте API-ключ в панели администрирования
3. Добавьте конфигурацию MCP-сервера в Claude Desktop
4. Начните с рабочего процесса только для чтения: поиск и аудит до того, как включите запись

[Документация MCP](/mcp/) содержит полный справочник API для всех 13 инструментов, включая типы параметров и схемы ответов.

Обслуживание документации не обязательно должно быть ручным процессом. Со структурированным протоколом между вашим ИИ-ассистентом и платформой документации утомительные части — поиск устаревшего контента, проверка согласованности, механические обновления — становятся тем, что можно делегировать с уверенностью.
